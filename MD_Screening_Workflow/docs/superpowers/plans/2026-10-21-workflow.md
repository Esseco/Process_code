# MD screening workflow implementation plan

**Goal:** 一个独立、可安装、可读的单结构 MLIP-MD 筛选工作流，直接复用 Process_MD。
**Architecture:** Python API + dataclass 配置；同一个 NVT 积分器连续运行，回调负责分析与调用审查函数。初始 5 ps 不参与生产 MSD；生产每 10 ps 分析一次，最多 200 ps。默认只记录、按预算运行，科学判据由后续 reviewer 提供。
**Tech stack:** Python >=3.10、Process_MD、ASE；沿用 Process_MLIP/pymatgen-diffusion。
**Spec:** 当前用户对通用库、低成本 MD 筛选及新 workflow 仓库的要求；本文件保存第一版的具体范围。

## Constraints and choices

- 新仓库 MD_Screening_Workflow；不移动/复制旧库，不改其科学算法。
- 处理一个已构建的 SOC 构型；不生成 SOC、不调度多个任务、不外推温度。
- 默认至少 200 原子、800 K、初始检查 5 ps、生产检查间隔 10 ps、生产预算 200 ps，总计最多 205 ps。
- 生产预算必须是检查间隔的整数倍，所有边界对齐保存帧。内部按初始检查步数和生产检查步数的最大公约数分块；只在 5、15、25…205 ps 做检查，保持同一积分器。
- 全程一个积分器；审查请求调整晶胞、温度或模型时保存建议并停止，暂不自动执行。
- 默认 continue 不等于骨架稳定；正 D/R² 不等于统计充分。sigma_NE 用 S/cm，D 用 cm²/s。
- 暂无严格跨进程 restart；不把末帧当 checkpoint，不提供伪恢复。
- 临时数据由 TemporaryDirectory 管理，默认 py1；不跑真实模型长 MD 验证程序接口。

## File map

`md_screening/config.py` 配置及单位/时间边界；`review.py` 检查报告与审查返回值；`analysis.py` 调用现有分析；`workflow.py` 连续运行、回调与持久化。
`examples/` Python 使用例；`tests/unit/` 契约与分段控制；`tests/integration/` 短 LJ MD 与合成扩散轨迹；`tools/verify.py` 临时测试和 wheel 验证。

## Review focus

热化帧误入 MSD；默认把估计当通过；200 ps 上限和非整段边界；采样不足被当程序错误或程序错误被吞掉；审查/分析异常后丢失已完成检查。
